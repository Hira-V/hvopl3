# Building hvopl3

hvopl3 is one C++ translation unit. Compile `src/hvopl3.cpp`, include `src/hvopl3.hpp`, and the
compiler's target macros select the accelerated paths: no configure step, no generated code at
build time.

```sh
c++ -std=c++17 -O2 -ffp-contract=off -Isrc -c src/hvopl3.cpp
```

C++17 or later. The library is freestanding: no allocation, no writable globals, no exceptions or
RTTI, and nothing from the C library but `memset`.

## Source files

| File | Contents |
|---|---|
| `src/hvopl3.hpp` | The API: `Chip`, `init`, `write`, `render`, `play`, the flags, and a C ABI (`hvopl3_*`) |
| `src/hvopl3.cpp` | Planning, the scalar kernels (the reference every other path matches), high quality, the mix and the register interface |
| `src/hvopl3_rvv.inc` | RVV kernels: across samples, across voices, high quality in float lanes, the mix |
| `src/hvopl3_dsp.inc` | The Andes DSP mix (the A25's `-mext-dsp`) |
| `src/hvopl3_tables.inc` | Log-sine, exponent, pan and gain tables; generated by `tools/gen_tables.py` and checked in |
| `src/hvopl3_test.hpp` | A hook for the test bench (the chip's own sample rate); not part of the API |

The `.inc` files are included by `hvopl3.cpp`; do not compile them separately. To regenerate the
tables, run `python3 -I tools/gen_tables.py src/hvopl3_tables.inc`.

## Targets

| Target | Typical flags | Path selected |
|---|---|---|
| Host, any 32/64-bit CPU | `-O2` | Scalar |
| Andes A25 (Hira-V) | `-mcpu=a25 -mext-dsp -O2 -DHVOPL_TOUCH_FIRST` | Andes DSP mix, A25-tuned kernels (from `__riscv_dsp`) |
| SiFive X280 | `-march=rv64gcv -O2` | RVV 1.0: kernels, high quality in float lanes, mix |
| T-Head C920 | `-march=rv64gc_xtheadvector -O2` | RVV 0.7.1: the same kernels and high quality |
| Tenstorrent T2 (Zve32x) | `-march=rv32imf_zve32x -mabi=ilp32f -O2` | RVV integer kernels and mix |
| RV32IMF cores | `-march=rv32imf -mabi=ilp32f -O2` | Scalar; no libc or libgcc needed beyond `memset` |

Add **`-ffp-contract=off` on every target.** The high-quality modes use float arithmetic, and a
fused multiply-add rounds differently: without the flag, high-quality output can differ between
targets. Chip mode (no high-quality flags) is integer-only and exact regardless.

The float paths assume the default rounding mode (round to nearest, ties to even).

## Build options

| Macro | Effect |
|---|---|
| `HVOPL_TOUCH_FIRST` | Touches each output buffer before rendering into it. For cores whose prefetcher follows a single stream, such as the A25 |
| `HVOPL_NO_DSP` | On a core with the Andes DSP extension, use the scalar path instead |
| `HVOPL3_DRV_MAX_CHIPS` | The MIDI driver (`drv/`) only: the most chips a `Driver` drives, 1..32 (default 32). Its arrays are sized by it: on the A25 the `Driver` is 7.7 KB at 4, 20.5 KB at 16 and 37.7 KB at 32 (the host: 8.5, 23.9 and 44.5 KB) |
| `HVOPL_NO_RTZ` | On RVV 1.0, convert floats the way the C920 must (it lacks round-toward-zero conversions), so its high-quality path can be tested under emulation |

## Version

`src/hvopl3.hpp` defines the version: `HVOPL3_VERSION_MAJOR`, `HVOPL3_VERSION_MINOR` and
`HVOPL3_VERSION_PATCH`, with `HVOPL3_VERSION` (the string, e.g. `"0.12.1"`) and
`HVOPL3_VERSION_NUMBER` (major × 10000 + minor × 100 + patch) built from them. `hvopl3::version()`
and `hvopl3_version()` return the compiled library's number. Releases are tagged `vMAJOR.MINOR.PATCH`
to match.

## Memory

All state is in one flat, caller-owned `hvopl3::Chip`, with no pointers inside; it can be copied,
placed in any memory, or allocated by the C ABI's caller using `hvopl3_chip_size()`.

| Build | `sizeof(Chip)` |
|---|---|
| Scalar | 6.1 KB |
| A25 (Andes DSP) | 7.3 KB |
| Zve32x | 8.9 KB |
| RVV 1.0 / 0.7.1 | 14.6 KB |

On the A25 the code is about 55 KB and the tables about 18 KB. The deepest call chain (the X280
build's high-quality path) uses about 1.4 KB of stack.
